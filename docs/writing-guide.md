# คู่มือเขียนบทความใน Pages CMS

คู่มือนี้สำหรับผู้เขียน ไม่ต้องรันโปรแกรมอะไรในเครื่อง เขียนและกดบันทึกใน Pages CMS ระบบจะสร้างและเผยแพร่เว็บให้เอง (วิธีเชื่อม Pages CMS กับ repo อยู่ใน `README.md` หัวข้อ "แก้เนื้อหาผ่าน Pages CMS" ส่วนที่พูดถึงการสร้างเว็บอัตโนมัติหลังบันทึกใช้ได้เมื่อตั้ง GitHub Actions ของ repo เสร็จแล้ว)

ดูตัวอย่างที่ใช้ทุกคำสั่งได้ที่บทความ **คู่มือเขียนบทความ (ตัวอย่างที่ใช้ทุกคำสั่ง)** ในเมนู บทความ (ไฟล์ `_guide.md` เป็นฉบับร่าง ไม่ขึ้นเว็บ ดูหน้าที่แสดงผลได้ที่ `<ที่อยู่เว็บ>/drafts/_guide.html`) อย่าเปลี่ยนสถานะเป็นเผยแพร่และอย่าลบ

## 1. เขียนบทความใหม่

1. เมนู **บทความ** → กดเพิ่มรายการใหม่ (Add an entry)
2. กรอก **ชื่อเรื่อง** แล้วดูช่อง **ชื่อไฟล์** ชื่อไฟล์คือที่อยู่ของบทความ (`articles/ชื่อไฟล์.html`) ต้องเป็นภาษาอังกฤษพิมพ์เล็ก ตัวเลข และ `-` เท่านั้น เช่น `organoid-intro.md` ถ้าชื่อเรื่องเป็นภาษาไทย ให้พิมพ์ชื่อไฟล์เอง และไม่ควรเปลี่ยนภายหลัง (ลิงก์เก่าจะเสีย)
3. กรอกช่องที่บังคับ: **ชื่อเรื่อง, หมวด, วันที่เผยแพร่, สถานะ**
4. ช่องอื่น: **คำโปรย** (1–2 ประโยคบนการ์ดและผลค้นหา), **ภาพปก**, **แหล่งอ้างอิง** (1 ช่อง = 1 รายการ), ช่องภาษาอังกฤษ (ไม่บังคับ) ช่อง "ชื่อสั้น", "ข้อความใต้ชื่อเรื่อง" และ "คำอธิบายสำหรับแชร์ลิงก์" ไม่บังคับ เว้นว่างไว้ได้ ระบบใช้ชื่อเรื่องและคำโปรย แทน
5. เขียนเนื้อหาในช่อง **เนื้อหา** (ดูข้อ 3)
6. ตั้งสถานะเป็น **ฉบับร่าง** ระหว่างเขียน กดบันทึก ตรวจหน้าที่ `<ที่อยู่เว็บ>/drafts/<ชื่อไฟล์>.html` (ใช้เวลาสร้างเว็บราวหนึ่งถึงสองนาทีหลังบันทึก) ฉบับร่างไม่ขึ้นหน้าแรก ไม่ขึ้นการค้นหา ไม่อยู่ใน sitemap และบอก Google ไม่ให้เก็บ
7. พร้อมแล้วเปลี่ยนสถานะเป็น **เผยแพร่** (ทำเช็กลิสต์ข้อ 6 ก่อน)

ถ้าบันทึกบทความที่เผยแพร่แล้วมีอะไรผิด (ขาดชื่อเรื่อง วันที่ หมวด รูปไม่มีคำอธิบายหรือเครดิต หรือคำศัพท์ที่ไม่มี) การสร้างเว็บจะล้ม เว็บเวอร์ชันที่ใช้งานอยู่ไม่ถูกแทนที่ และ GitHub Actions แสดงรายการที่ต้องแก้ แก้แล้วบันทึกใหม่

## 2. ใส่รูป

**ภาพปก** (ช่อง "ภาพปก (สไลด์)"): กด เพิ่ม แล้วเลือกชนิด

- **เกลียว DNA** และ **ภาพโปรตีนระบายสี**: ภาพที่ระบบวาดให้ ไม่ต้องใช้รูป ใส่แค่คำบรรยาย
- **รูปภาพจริง**: อัปโหลดรูป แล้วกรอก **คำอธิบายรูป (alt)** และ **เครดิต** (บังคับ) ใส่หลายภาพจะกลายเป็นสไลด์ ใส่ภาพเดียวเป็นภาพนิ่ง รูปแรกที่เป็นรูปจริงยังถูกใช้เป็นภาพตอนแชร์ลิงก์ด้วย (ถ้าไม่มี ใช้ภาพโลโก้ของเว็บ)

**รูปในเนื้อหา:**

1. เมนู **Media** → **รูปในเนื้อหาบทความ** → อัปโหลดรูป (jpg, jpeg, png, webp) ระบบเปลี่ยนชื่อไฟล์เป็นชื่อสุ่ม ให้ดูชื่อไฟล์ที่ได้
2. ในเนื้อหา เขียนคำสั่ง (ดูข้อ 3) ใส่ชื่อไฟล์ที่ได้ใน `src`

**ทุกรูปต้องมี alt และ credit**

- **alt** = อธิบายสิ่งที่เห็นในรูปให้คนที่มองไม่เห็นรูปเข้าใจ เช่น "แผนภาพ Cas9 ตัด DNA สองสายตรงตำแหน่งที่ติดกับ PAM" (ไม่ใช่ชื่อไฟล์ หรือคำว่า "รูป")
- **credit** = ใครสร้าง/มาจากไหน เช่น "กรวิชญ์ บัวดำ" หรือชื่อผู้สร้างและแหล่งที่มา (ถ้ามีสัญญาอนุญาต ใส่ด้วย) ห้ามใส่เครดิตที่ไม่แน่ใจ ถ้ายังไม่รู้ ยังไม่เผยแพร่รูปนั้น
- ใช้เฉพาะรูปที่มีสิทธิ์ใช้ รูปจากเว็บอื่นต้องมีสัญญาอนุญาตที่ให้ใช้ได้

ขนาดไฟล์: ปกควรกว้างอย่างน้อย 1600 px รูปในเนื้อหากว้างอย่างน้อย 1200 px ไม่ต้องย่อก่อนอัปโหลด ระบบย่อให้เอง (เป็น WebP ขนาด 800 และ 1600 px) และไม่ขยายรูปที่เล็กกว่านั้น

## 3. เขียนเนื้อหา (Markdown และคำสั่งย่อ)

ช่องเนื้อหาเป็นช่องโค้ด เขียนเป็น Markdown ตามนี้

| อยากได้ | เขียนว่า |
|---|---|
| หัวข้อหลัก / หัวข้อย่อย | `## หัวข้อหลัก` / `### หัวข้อย่อย` (อย่าใช้ `#` เดี่ยว เพราะชื่อเรื่องเป็นหัวข้อหลักของหน้าอยู่แล้ว) |
| ตัวหนา / ตัวเอียง | `**ตัวหนา**` / `*ตัวเอียง*` |
| ลิงก์ | `[ข้อความ](https://ที่อยู่เว็บ)` |
| รายการข้อ | ขึ้นบรรทัดด้วย `- ` หรือ `1. ` |
| ข้อความเด่น | `> ประโยคสำคัญ` |
| ตาราง | `\| หัวคอลัมน์ \| หัวคอลัมน์ \|` แล้วบรรทัด `\| --- \| --- \|` แล้วแถวข้อมูล |
| ย่อหน้าใหม่ | เว้นหนึ่งบรรทัดว่าง |
| ช่องที่ยังรอข้อมูล | ย่อหน้าที่มีแค่ `[ข้อความ]` จะแสดงเป็นช่องสีจาง |

หัวข้อทุกอันขึ้นในสารบัญเอง ถ้าอยากให้ลิงก์ตรงหัวข้อ ใส่ `{#ชื่อ}` ท้ายหัวข้อ เช่น `## บทนำ {#intro}`

**คำสั่งย่อ** (พิมพ์ตามนี้ทุกตัวอักษร ตัวพิมพ์เล็ก)

**คำศัพท์ที่มีกล่องอธิบาย** `[[key|ข้อความ]]`

- ตัวอย่าง `[[pam|PAM]]` → คำว่า PAM มีเส้นประใต้คำ ชี้หรือแตะแล้วขึ้นกล่องอธิบาย
- `key` ต้องมีในเมนู **คำศัพท์** (ปัจจุบัน: `hgp`, `grna`, `pam`, `offtarget`) ข้อความหลังเส้นตั้งเป็นคำที่อยู่ในประโยค เปลี่ยนได้ตามต้องการ
- คำใหม่: เมนู คำศัพท์ → เพิ่มรายการ ใส่ key (ภาษาอังกฤษพิมพ์เล็ก ไม่ซ้ำ) ชื่อคำ และคำอธิบาย
- ถ้าพิมพ์ key ที่ไม่มี การสร้างเว็บจะล้มและบอกชื่อ key นั้น
- **ในตาราง** ต้องเขียนเส้นตั้งเป็น `\|` เช่น `[[pam\|PAM]]` (ไม่งั้นตารางแตกคอลัมน์)

**แผนภาพกลไก CRISPR-Cas9** `{{mech}}` อยู่บรรทัดของตัวเอง ใช้ในบทความที่อธิบาย CRISPR เท่านั้น แผนภาพกดเล่นทีละขั้นได้ ข้อความขั้นตอนแก้ที่เมนู แผนภาพกลไก

**รูป** `{{figure src="ชื่อไฟล์.jpg" alt="อธิบายรูป" caption="คำบรรยาย" credit="ผู้สร้าง"}}` อยู่บรรทัดของตัวเอง

- `src` ชื่อไฟล์ที่อัปโหลดไว้ใน Media → รูปในเนื้อหาบทความ (เว้นว่างได้ = ช่องรอรูป)
- `alt` และ `credit` บังคับเมื่อมีรูป `caption` ไม่บังคับ
- เขียนอัญประกาศคู่ `"` ล้อมทุกค่า และห้ามมีอัญประกาศคู่อยู่ในข้อความของค่านั้น

**กล่องเปรียบเทียบสองฝั่ง**

```
{{duo}}
**ป้ายซ้าย**

ข้อความซ้าย

---

**ป้ายขวา**

ข้อความขวา
{{/duo}}
```

บรรทัดแรกของแต่ละฝั่งเป็นป้ายตัวหนา คั่นสองฝั่งด้วยบรรทัด `---` บรรทัดเดียว ฝั่งแรกใช้สีเน้น

ห้ามเขียน HTML ในเนื้อหา (ระบบไม่แสดง) ใช้ Markdown และคำสั่งย่อด้านบน

## 4. วางจาก Google Docs

ช่องเนื้อหาเป็นข้อความธรรมดา ถ้าวางจาก Docs ตรงๆ จะได้แค่ตัวอักษร หัวข้อ ตัวหนา ตาราง ลิงก์ และรูปหายหมด ทางที่ง่ายที่สุด:

1. ใน Google Docs เลือกข้อความที่ต้องการ → คลิกขวา → **Copy as Markdown** (ถ้าไม่มีเมนูนี้ ใช้เมนู ไฟล์ → ดาวน์โหลด → **Markdown (.md)** แล้วเปิดไฟล์ด้วย Notepad คัดลอกข้อความ)
2. วางในช่องเนื้อหา แล้วแก้ตามนี้
   - **หัวข้อ:** ถ้าได้ `#` เดี่ยว เปลี่ยนเป็น `##` (และ `##` เดิมเป็น `###`) ระดับหัวข้อห้ามข้าม (ห้ามมี `###` ก่อนมี `##`)
   - **รูป:** Docs ส่งรูปมาเป็นข้อความยาวมากหรือแท็ก `![][image1]` **ลบทิ้งทั้งหมด** (รวมบล็อกข้อความยาวๆ ท้ายเอกสารที่ขึ้นต้น `[image1]: <data:image...`) แล้วอัปโหลดรูปเองตามข้อ 2 และใช้ `{{figure ...}}`
   - **ตัวอักษร `\`** ที่ Docs เติมหน้าเครื่องหมายบางตัว เช่น `\.` `\-` `\(` ลบออกได้ ยกเว้น `\|` ในตาราง
   - **ตาราง** มาเป็นตาราง Markdown ใช้ได้ ตรวจว่าบรรทัดที่สองเป็น `| --- | --- |`
   - **ลิงก์** มาเป็น `[ข้อความ](ที่อยู่)` ตรวจว่าไม่มีลิงก์ของ Google (`google.com/url?q=...`) ถ้ามีให้แก้เป็นที่อยู่จริง
   - **เชิงอรรถ** ไม่ได้มาด้วย ให้ย้ายไปช่อง **แหล่งอ้างอิง** (1 รายการต่อ 1 ช่อง)
   - **ช่องว่างและบรรทัด:** ย่อหน้าต้องคั่นด้วยบรรทัดว่างหนึ่งบรรทัด
3. ใส่คำสั่งย่อ (คำศัพท์ แผนภาพ กล่องเปรียบเทียบ) ที่ต้องการ

**ห้ามวางข้อความที่คัดลอกมาจากบทความหรือเว็บอื่นโดยไม่เขียนใหม่และไม่อ้างอิง**

## 5. แปลเป็นอังกฤษ

ระบบมีให้แค่ช่อง **ชื่อเรื่อง (อังกฤษ)** และ **คำโปรย (อังกฤษ)** เนื้อหาบทความฉบับอังกฤษเป็นหน้าแยก (`articles/en/<ชื่อไฟล์>.html`) ที่ผู้เขียนเขียนเอง ระบบไม่แปลให้ ถ้ายังไม่มีฉบับอังกฤษ ผู้อ่านที่เลือก EN จะเห็นแถบแจ้งว่ายังไม่มีฉบับอังกฤษ

## 6. เช็กลิสต์ก่อนเผยแพร่

- [ ] ชื่อเรื่อง คำโปรย หมวด และวันที่ถูกต้อง
- [ ] เปิดดูหน้าฉบับร่าง (`/drafts/<ชื่อไฟล์>.html`) บนมือถือและคอมพิวเตอร์ ไม่มีข้อความที่ผิดรูป (เช่น เห็น `{{` หรือ `[[` ค้างอยู่ในหน้า แปลว่าพิมพ์คำสั่งผิด)
- [ ] ไม่เหลือช่องรอข้อมูล `[ ... ]` (ค้นหาเครื่องหมาย `[` ในช่องเนื้อหา คำโปรย คำบรรยายภาพ แหล่งอ้างอิง) หรือเหลือเฉพาะที่ตั้งใจ
- [ ] ทุกรูปมี **alt** และ **credit** จริง ไม่ใช่ชื่อไฟล์ และรูปที่ใช้มีสิทธิ์ใช้
- [ ] ข้อเท็จจริงทางวิทยาศาสตร์ ตัวเลข และชื่อเฉพาะ ตรวจกับแหล่งที่เชื่อถือได้แล้ว และใส่ใน **แหล่งอ้างอิง**
- [ ] คำศัพท์เฉพาะที่ผู้อ่านอาจไม่รู้ ใส่ `[[key|คำ]]` อย่างน้อยที่คำแรกที่ปรากฏ
- [ ] หัวข้อไล่ระดับถูก (`##` แล้ว `###`) และสารบัญในหน้าฉบับร่างดูสมเหตุสมผล
- [ ] ตารางกว้างๆ เลื่อนดูได้บนมือถือ (ระบบทำให้เอง ตรวจว่าอ่านรู้เรื่อง)
- [ ] เปลี่ยนสถานะเป็น **เผยแพร่** แล้วบันทึก รอสร้างเว็บ แล้วเปิดหน้าจริง `<ที่อยู่เว็บ>/articles/<ชื่อไฟล์>.html` ตรวจอีกครั้ง
- [ ] ถ้าการสร้างเว็บล้ม (ดูที่แท็บ Actions ของ repo บน GitHub) อ่านรายการที่ต้องแก้ แก้ แล้วบันทึกใหม่

## ปัญหาที่พบบ่อย

| อาการ | สาเหตุและวิธีแก้ |
|---|---|
| สร้างเว็บล้ม ข้อความ `glossary key "xxx"` | key คำศัพท์ไม่มีในเมนู คำศัพท์ แก้ตัวสะกด หรือเพิ่มคำนั้น |
| สร้างเว็บล้ม ข้อความ `has no alt text` / `has no credit` | รูปขาดคำอธิบายหรือเครดิต กรอกให้ครบ |
| สร้างเว็บล้ม ข้อความ `is not in media/...` | ชื่อไฟล์รูปไม่ตรงกับที่อัปโหลด หรือยังไม่ได้อัปโหลด |
