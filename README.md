## รันดูในเครื่อง

หน้าแรก หน้าโปรเจกต์ และช่องค้นหาโหลดข้อมูลจาก `data/*.json` ด้วย `fetch` ซึ่งเบราว์เซอร์ไม่อนุญาตเมื่อเปิดไฟล์ตรงๆ (`file://`) ถ้าดับเบิลคลิก `index.html` จะเห็นข้อความแจ้งว่าโหลดเนื้อหาไม่สำเร็จ ให้รันผ่านเซิร์ฟเวอร์ในเครื่องแทน เปิดเทอร์มินัลในโฟลเดอร์นี้แล้วรัน

```bash
python -m http.server 8000
```

จากนั้นเปิด `http://localhost:8000` (ถ้าไม่มี Python ใช้ `npx serve` ก็ได้) บน GitHub Pages ใช้งานได้ตามปกติ ไม่ต้องตั้งค่าอะไรเพิ่ม

## เพิ่มบทความใหม่

1. คัดลอก `articles/_template.html` เป็นไฟล์ใหม่ เช่น `articles/organoid.html` (ชื่อไฟล์ = `slug`)
2. แก้ทุกจุดที่เป็น `[ ]` ในไฟล์ใหม่ (ชื่อเรื่อง คำโปรย meta แชร์ลิงก์ ภาพปก เนื้อหา แหล่งอ้างอิง) และใส่ slug ที่ `<html data-slug="...">` คอมเมนต์ในเทมเพลตบอกว่าแก้ตรงไหนและทำไม ลบบรรทัด `<meta name="robots" content="noindex">` ออกด้วย
3. เปิด `data/articles.json` แล้วเพิ่มรายการใหม่ต่อท้าย แค่นี้หน้าแรก รายการ "ล่าสุด" จำนวนในการ์ดหมวด และช่องค้นหาจะอัปเดตเอง ไม่ต้องแก้ `index.html` หรือ `main.js`

```json
{
  "slug": "organoid",
  "title": "ชื่อบทความ",
  "dek": "คำโปรยสั้นๆ",
  "category": "biotech",
  "date": "2026-12-05",
  "title_en": "",
  "dek_en": "",
  "covers": [{ "type": "helix", "caption": "", "credit": "" }],
  "featured": false,
  "status": "published",
  "has_en": false
}
```

| ช่อง | ความหมาย |
|---|---|
| `slug` | ต้องตรงกับชื่อไฟล์ `articles/<slug>.html` |
| `category` | `medicine`, `biotech`, `bioinformatics`, `ai` หรือ `notes` |
| `date` | `YYYY-MM-DD` หรือ `YYYY-MM` (ถ้ายังไม่รู้วัน) เป็นปี ค.ศ. เว็บจะแสดงเป็น พ.ศ. ให้เอง ใช้เรียงลำดับ "ล่าสุด" |
| `covers` | รายการภาพปกของบทความ (สไลด์ภาพปกบนหน้าแรกและหัวบทความ) ดูหัวข้อ "ภาพปกแบบสไลด์" ถ้าไม่ใส่ จะใช้ภาพเกลียว DNA ภาพเดียว |
| `featured` | `true` = ขึ้นเป็นบทความเด่นบนหน้าแรก ถ้ามีหลายเรื่อง จะใช้เรื่องที่ใหม่สุด ถ้าไม่มีเรื่องไหนเป็น `true` จะใช้เรื่องใหม่สุดแทน |
| `status` | `published` = แสดงบนเว็บ, `draft` = ไม่ขึ้นในรายการ จำนวนหมวด และการค้นหา |
| `has_en` | `true` เมื่อมีฉบับอังกฤษที่ `articles/en/<slug>.html` แล้วเท่านั้น (ดูหัวข้อ "ภาษา TH/EN") ค่าเริ่มต้น `false` |
| `title_en`, `dek_en` | ไม่บังคับ ชื่อและคำโปรยภาษาอังกฤษสำหรับหน้ารายการและการค้นหาตอนเลือก EN ถ้าเป็น `""` จะแสดงข้อความไทย |

ข้อควรระวัง: `draft` ซ่อนแค่ในรายการและช่องค้นหา ไฟล์ `articles/<slug>.html` ยังเปิดได้ถ้ามีคนรู้ลิงก์ ถ้าไม่อยากให้ใครเห็น อย่าเพิ่งอัปโหลดไฟล์นั้นขึ้น GitHub

### ภาพปกแบบสไลด์

ภาพปกของแต่ละบทความ (บทความเด่นบนหน้าแรกและหัวหน้าบทความ) สร้างจากช่อง `covers` ใน `data/articles.json` ไม่ต้องแก้ HTML เป็นรายการภาพ แต่ละภาพมี `type`

| `type` | ภาพที่ได้ |
|---|---|
| `helix` | เกลียว DNA ที่หมุนเองและหมุนตามเมาส์ หยุดเมื่อเลื่อนพ้นจอหรือไม่ใช่สไลด์ปัจจุบัน |
| `fold` | ภาพประกอบโปรตีนที่วาดขึ้นทีละส่วน ระบายสีตาม pLDDT (>90 `#0053D6`, 70–90 `#65CBF3`, 50–70 `#FFDB13`, <50 `#FF7D45`) พร้อมคำอธิบายสี สีเหล่านี้เป็น token `--plddt-*` ใน `style.css` |
| `image` | รูปจริง ใส่ไฟล์ใน `assets/img/covers/` แล้วใส่เฉพาะชื่อไฟล์ที่ `src` (หรือ path เต็มจากรากเว็บ / URL `https://`) `src` ว่าง = แสดงช่อง `[รูปปกของคุณ]` |

```json
"covers": [
  { "type": "helix", "caption": "คำบรรยายภาพนี้", "credit": "" },
  { "type": "fold",  "caption": "ภาพประกอบโครงสร้างโปรตีน", "credit": "" },
  { "type": "image", "src": "organoid-cover.webp", "alt": "อธิบายสิ่งที่เห็นในรูป", "caption": "คำบรรยาย", "credit": "ชื่อผู้ถ่าย / แหล่งที่มา" }
]
```

ช่องของแต่ละภาพ: `caption` (คำบรรยายใต้ภาพบนหน้าบทความ), `credit` (แสดงเป็น "ภาพ: ..." ถ้าว่างจะไม่แสดง), `alt` (ข้อความแทนรูป ใช้กับ `image` ถ้าไม่ใส่จะใช้ `caption`) ไม่บังคับ: `caption_en`, `credit_en`, `alt_en` สำหรับภาษาอังกฤษ

- **ภาพเดียว** = ภาพนิ่ง ไม่มีลูกศร จุด หรือเลื่อนเอง (เกลียว DNA ยังหมุนอยู่ เพราะเป็นตัวภาพเอง) **หลายภาพ** = สไลด์: ลูกศร จุด ปัดบนมือถือ ลูกศรซ้าย/ขวาบนคีย์บอร์ด และเลื่อนเองทุก 5 วินาทีพร้อมแถบความคืบหน้า หยุดเมื่อ hover, โฟกัสอยู่ในสไลด์, แท็บไม่ได้เปิดอยู่ หรือสไลด์พ้นจอ ลากแล้วจะไม่เผลอกดลิงก์
- คำบรรยายและเครดิตใต้ภาพบนหน้าบทความเปลี่ยนตามสไลด์ ในหน้าแรกแต่ละสไลด์ลิงก์ไปบทความ
- รูปแรกของสไลด์โหลดทันที (เป็นภาพที่เห็นตอนเข้าหน้า จึงไม่ใช้ `loading="lazy"`) รูปถัดไปเป็น `loading="lazy"`
- ถ้าตั้งค่าลดการเคลื่อนไหวในระบบ: ไม่เลื่อนเอง ไม่หมุน และภาพโปรตีนแสดงครบทันที ปุ่มและคีย์บอร์ดยังใช้ได้
- ย่อรูปก่อนด้วย `scripts/optimize-images.py` (วางต้นฉบับใน `img-src/covers/`)

## คอมโพเนนต์ในบทความ

คอมโพเนนต์สองอย่างที่ใส่ในบทความไหนก็ได้ ตัวอย่างจริงอยู่ใน `articles/crispr-alphafold.html` และคอมเมนต์วิธีใช้อยู่ใน `articles/_template.html` (ไทย) กับ `articles/en/_template.html` (อังกฤษ) หน้าบทความใหม่ที่คัดลอกจากเทมเพลตมีไฟล์ของทั้งสองอย่างเชื่อมไว้แล้ว

### คำศัพท์ (glossary)

คำที่มีกล่องอธิบายตอน hover หรือ Tab ไปโฟกัส เขียนในบทความแบบนี้

```html
<button type="button" class="term" data-term="pam">PAM</button>
```

- `data-term` คือ `key` ของคำใน `data/glossary.json` คำอธิบายเขียนที่ไฟล์นั้น ไม่ได้เขียนในบทความ ข้อความในปุ่มเป็นคำที่อยู่ในประโยคตามปกติ (ไม่ต้องตรงกับ `term`)
- key ที่มีอยู่แล้ว: `hgp` (Human Genome Project), `grna` (guide RNA), `pam` (PAM), `offtarget` (off-target)
- เพิ่มคำใหม่โดยเพิ่มรายการต่อท้ายใน `data/glossary.json`

```json
{ "key": "indel", "term": "indel", "term_en": "", "definition": "คำอธิบายสั้นๆ ของคำนี้", "definition_en": "" }
```

| ช่อง | ความหมาย |
|---|---|
| `key` | ตัวพิมพ์เล็ก ไม่มีเว้นวรรค ไม่ซ้ำกัน ใช้ใน `data-term` |
| `term` | ชื่อที่ขึ้นเป็นหัวกล่อง |
| `definition` | คำอธิบาย (ไทย) |
| `term_en`, `definition_en` | ไม่บังคับ ฉบับอังกฤษ ถ้าว่างจะแสดงข้อความไทยในกล่อง |

**พฤติกรรม**
- hover หรือโฟกัสด้วยคีย์บอร์ด = กล่องขึ้น (ออกจากคำ/เลื่อนโฟกัสออก = หาย)
- **คลิก หรือแตะบนมือถือ** = ปักกล่องค้างไว้ จนกว่าจะแตะข้างนอก แตะคำอื่น หรือกด `Esc` (Esc คืนโฟกัสให้คำเดิม)
- กล่องไม่ล้นขอบจอ: ถูกจำกัดให้อยู่ในขอบซ้ายขวา และกลับไปอยู่เหนือคำถ้าด้านล่างไม่พอ
- key ที่ไม่มีใน `glossary.json` จะเป็นคำธรรมดา (ไม่มีกล่อง) และ `scripts/check-site.py` จะแจ้งเตือน
- โค้ด: `assets/js/glossary.js`, `assets/css/glossary.css`

### แผนภาพกลไก CRISPR-Cas9

ใส่ `div` ว่างอันเดียวในบทความ JavaScript สร้างที่เหลือเองทั้งหมด

```html
<div data-mech></div>
```

สิ่งที่ได้: แผนภาพ DNA กับ Cas9, สามขั้นตอนที่กดได้, ปุ่มสลับ NHEJ/HDR, ปุ่ม "เล่น" (เล่นทุกขั้นอัตโนมัติ กดอีกทีเพื่อหยุด) กับ "เริ่มใหม่", และการ์ด NHEJ/HDR ใต้แผนภาพ

- ขั้น 1 Cas9 เลื่อนไปหา PAM · ขั้น 2 ตัด DNA สายคู่ · ขั้น 3 ซ่อมแซมแบบ NHEJ หรือ HDR
- คำบรรยายใต้แผนภาพเป็น `aria-live` โปรแกรมอ่านหน้าจอจะอ่านทุกครั้งที่เปลี่ยนขั้น
- กดการ์ด NHEJ หรือ HDR ใต้แผนภาพ = ไปที่ขั้น 3 ด้วยวิธีนั้น (และเลื่อนหน้าไปที่แผนภาพ)
- บนมือถือตัวหนังสือในแผนภาพถูกขยายให้อ่านออก (ตรวจที่ 375px ตัวอักษรในแผนภาพไม่เล็กกว่า 12px และไม่ชนกันทุกขั้นทั้งไทยและอังกฤษ)
- ข้อความอธิบายแต่ละขั้นและการ์ดแก้ที่ `data/mechanism.json` (`step`, `caption`, `label`, `desc` และ `*_en` ไม่บังคับ) ส่วนป้ายและปุ่ม (เป้าหมาย, ตัดตรงนี้, เล่น, เริ่มใหม่ ...) อยู่ใน `data/i18n.json` ขึ้นต้นด้วย `mech.`
- แผนภาพนี้เป็นของ CRISPR-Cas9 โดยเฉพาะ ถ้าใส่ในบทความอื่นจะเป็นแผนภาพเดิม
- ถ้าลดการเคลื่อนไหวในระบบ: ขั้นเปลี่ยนทันทีไม่มีการเลื่อน (ปุ่มเล่นยังเล่นลำดับขั้นให้)
- โค้ด: `assets/js/mechanism.js`, `assets/css/mechanism.css`

## ภาษา TH/EN

ปุ่ม TH/EN ทำงานทั้งเว็บ ข้อความเมนู ปุ่ม ป้าย และข้อความแจ้งเตือนทุกข้อความอยู่ใน **`data/i18n.json`** ที่เดียว (`"th"` และ `"en"` ใช้ key ชุดเดียวกัน) แก้ข้อความหรือเพิ่มข้อความใหม่ที่ไฟล์นี้ ไม่ต้องแก้ `main.js` ข้อความไทยที่เขียนไว้ใน HTML เป็นแค่ตัวสำรองตอนที่ JavaScript ใช้ไม่ได้ ถ้าแก้คำที่ผู้ใช้เห็น ให้แก้ใน `i18n.json` ไม่ใช่ใน HTML

องค์ประกอบใน HTML ผูกกับข้อความด้วย `data-i18n="key"` (ข้อความ), `data-i18n-ph="key"` (placeholder) และ `data-i18n-aria="key"` (aria-label) ข้อความที่ JavaScript สร้าง (การ์ด ป้ายจำนวนบทความ ปุ่ม) ใช้ key เดียวกัน

**ตัวเลือกภาษาจำไว้ในเบราว์เซอร์** เลือก EN ครั้งเดียวแล้วทุกหน้าเป็นอังกฤษ

**เนื้อหาที่ยังไม่มีฉบับอังกฤษ** (เนื้อหาบทความ หน้าเกี่ยวกับฉัน พอร์ตโฟลิโอ ชื่อบทความที่ไม่มี `title_en`) แสดงเป็นภาษาไทยตามเดิม ระบบไม่แปลให้ หน้าบทความภาษาไทยที่ยังไม่มีฉบับอังกฤษจะขึ้นแถบ "This article is only available in Thai for now."

**วันที่:** ภาษาไทยแสดงเป็น พ.ศ. (เช่น 5 พฤศจิกายน 2569) ภาษาอังกฤษแสดงเป็น ค.ศ. (5 November 2026) ใน `articles.json` เก็บเป็น ค.ศ. เสมอ (`YYYY-MM-DD`) รูปแบบวันที่และชื่อเดือนอยู่ใน `i18n.json` (`date.*`) ปี © ท้ายหน้าก็เปลี่ยนตามภาษา

**`lang` ของหน้า:** `<html lang>` บอกภาษาของ "เนื้อหาในไฟล์" ไฟล์ปกติเป็น `th` ไฟล์ใน `articles/en/` เป็น `en` ห้ามเปลี่ยนเอง ส่วนข้อความที่สลับเป็นอังกฤษบนหน้าไทยจะถูกใส่ `lang="en"` ให้ที่องค์ประกอบนั้น (และ `lang="th"` ให้ข้อความไทยบนหน้าอังกฤษ) เพื่อให้โปรแกรมอ่านหน้าจออ่านถูกภาษา

**ชื่อผู้เขียนภาษาอังกฤษ:** ใส่ `name_en` และ `initials_en` ใน `data/site.json` ถ้าเว้นว่าง หน้าอังกฤษจะแสดงชื่อไทย

### บทความภาษาอังกฤษ

ผมไม่ได้แปลบทความให้ ระบบรองรับไฟล์ที่คุณเขียนเอง

1. ต้องมีบทความภาษาไทยก่อน (`articles/<slug>.html` และรายการใน `data/articles.json`)
2. คัดลอก `articles/en/_template.html` เป็น `articles/en/<slug>.html` (ใช้ slug เดียวกับฉบับไทย) แล้วใส่ slug ที่ `<html data-slug="...">` เขียนเนื้อหาอังกฤษแทนข้อความใน `[ ]` ลบบรรทัด `noindex` ออก ห้ามเปลี่ยน `lang="en"`
3. ใน `data/articles.json` ตั้ง `"has_en": true` (และใส่ `title_en`, `dek_en` ถ้าต้องการให้หน้ารายการแสดงชื่ออังกฤษ)
4. **hreflang:** ในฉบับอังกฤษมีบล็อก `<link rel="alternate" hreflang=...>` พร้อมแล้ว ใส่ `[URL เว็บ]` เป็นที่อยู่เว็บจริง และในฉบับไทยให้เปิดบล็อก hreflang ที่คอมเมนต์ไว้ใน `<head>` (ดูใน `articles/_template.html`) ให้สองไฟล์ชี้หากัน `x-default` ชี้ไปฉบับไทย
5. ก่อนตั้ง `has_en: true` ต้องมีไฟล์อังกฤษอยู่จริง ไม่เช่นนั้นลิงก์ภาษาอังกฤษจะ 404

**พฤติกรรมเมื่อมีฉบับอังกฤษ**
- กด EN ในหน้าบทความไทย → ไปหน้าอังกฤษของบทความนั้น (รักษา `#หัวข้อ` ไว้)
- กด TH ในหน้าอังกฤษ → ไปหน้าไทย
- เลือก EN ไว้แล้วเปิดลิงก์ไทยของบทความที่มีฉบับอังกฤษ → พาไปหน้าอังกฤษเอง (กด TH เพื่อกลับ)
- ลิงก์บทความในหน้าแรก รายการ ก่อนหน้า/ถัดไป ในหมวดเดียวกัน และผลค้นหา ชี้ไปฉบับอังกฤษอัตโนมัติเมื่อเลือก EN และบทความนั้น `has_en: true`
- บทความที่ไม่มีฉบับอังกฤษ: อยู่ที่หน้าไทย ขึ้นแถบแจ้ง

## ก่อนเผยแพร่บทความ (checklist)

- [ ] **สถานะ:** `status` ใน `data/articles.json` เป็น `"published"` (ระหว่างเขียนใช้ `"draft"`)
- [ ] **วันที่:** `date` ถูกต้องในรูป `YYYY-MM-DD` (เป็นปี ค.ศ.) และเปิดหน้าบทความแล้วเห็นวันที่ขึ้นใน meta bar
- [ ] **ไม่เหลือ `[ ]`:** ค้นหาอักขระ `[` ในไฟล์บทความทั้ง `<head>` และเนื้อหา ไม่ควรเหลือช่องรอข้อมูล (รวมถึง `[URL เว็บ]` ใน meta แชร์ลิงก์)
- [ ] **ภาพและเครดิต:** ทุกรูปมี `alt` `width` `height` `loading="lazy"` และ figcaption ที่ระบุผู้สร้างหรือแหล่งที่มา รูปที่ไม่ได้ทำเองต้องมีสิทธิ์ใช้งานและเครดิตครบ ภาพปกใน `covers` ของ JSON มีไฟล์รูปอยู่ใน `assets/img/covers/` จริง มี caption/alt และเครดิตครบ (ไม่เหลือ `[ ]`)
- [ ] **แหล่งอ้างอิง:** แทนที่ `[แหล่งอ้างอิง 1..]` ด้วยแหล่งจริงทั้งหมด ข้อเท็จจริง ตัวเลข และปีในเนื้อหามีที่มาให้ตรวจสอบได้
- [ ] **ข้อความตรงกัน:** ชื่อเรื่อง คำโปรย หมวด ใน JSON ตรงกับ `<h1>`, `<title>`, `description`, `og:title`, `og:description`
- [ ] **แชร์ลิงก์:** `og:url`, `og:image`, `twitter:image` เป็น URL เต็ม (`https://...`) ของเว็บจริง รูปปกขนาดประมาณ 1200x630 เป็น .jpg/.png ลองวาง URL ในเครื่องมือดูตัวอย่างลิงก์ของแพลตฟอร์ม (เช่น Facebook Sharing Debugger) หลังขึ้นเว็บ
- [ ] **ฉบับอังกฤษ (ถ้ามี):** `has_en: true` ตรงกับไฟล์ `articles/en/<slug>.html` ที่มีจริง ไม่เหลือ `[ ]` ตัวเลขและข้อเท็จจริงตรงกับฉบับไทย บล็อก hreflang ของสองไฟล์ชี้หากัน และกด TH/EN สลับไปมาได้ถูก
- [ ] **ลบ noindex:** ลบ `<meta name="robots" content="noindex">` ที่ติดมาจากเทมเพลต
- [ ] **ทดสอบ:** เปิดผ่านเซิร์ฟเวอร์ในเครื่อง ดูที่ความกว้าง 375px ไม่มี scroll แนวนอน สารบัญกดแล้วเลื่อนถูกหัวข้อ ปุ่มก่อนหน้า/ถัดไปและบทความในหมวดเดียวกันลิงก์ถูก

## เพิ่มโปรเจกต์ใหม่

โปรเจกต์แต่ละอันมีหน้ารายละเอียดของตัวเองที่ `projects/<slug>.html` การ์ดในหน้าโปรเจกต์และผลค้นหาลิงก์ไปที่หน้านี้ (ลิงก์เว็บจริงกับ GitHub อยู่ในหน้ารายละเอียด)

1. เปิด `data/projects.json` แล้วเพิ่มรายการต่อท้าย (ช่องต่างๆ ดูตารางด้านล่าง) การ์ด ตัวกรองประเภท และช่องค้นหาจะอัปเดตเอง
2. คัดลอก `projects/_template.html` เป็น `projects/<slug>.html` (ชื่อไฟล์ = `slug`) แล้วแก้ `data-project="<slug>"` และ `[slug]` `[ชื่อโปรเจกต์]` `[คำอธิบายสั้น]` ใน `<head>` ลบบรรทัด `<meta name="robots" content="noindex">` ออก และอย่าลืมค่า `[URL เว็บ]` ของ meta แชร์ลิงก์
3. เขียนเนื้อหาแทนข้อความใน `[ ]`: ปัญหาที่อยากแก้ → วิธีทำและเครื่องมือที่ใช้ → ผลลัพธ์ (ภาพหน้าจอ) → สิ่งที่ได้เรียนรู้ ส่วนที่ยังไม่มีข้อมูลให้คงช่อง `[ ]` ไว้ ห้ามแต่ง

ชื่อ คำอธิบายหัวหน้า ป้ายประเภท/แท็ก อักษรย่อบนภาพหัว สารบัญ และปุ่มเปิดเว็บจริง/GitHub เติมอัตโนมัติจาก `data/projects.json` ตาม `slug` ถ้า `url` หรือ `github` ยังเป็น `""` ปุ่มท้ายหน้าจะขึ้นเป็นช่อง `[ลิงก์เว็บจริง]` / `[ลิงก์ GitHub]` และปุ่มหัวหน้าจะไม่แสดง ถ้า `slug` ในหน้าไม่ตรงกับ JSON จะขึ้นข้อความ "ไม่พบโปรเจกต์นี้"

### ภาพหน้าจอที่กดขยายได้

ครอบ `<img>` ด้วย `<button type="button" class="zoom-btn" data-zoom aria-label="ขยายภาพ">` (ตัวอย่างเต็มอยู่ในเทมเพลต) กดแล้วขยายเต็มจอ ปิดด้วย Esc คลิกนอกภาพ หรือปุ่มปิด คำบรรยายและเครดิตใน `<figcaption>` จะแสดงใต้ภาพขยายด้วย ใส่ `data-full="path"` ที่ปุ่มถ้าอยากให้ตอนขยายใช้ไฟล์ความละเอียดสูงกว่า ใช้ได้ในหน้าบทความด้วย รูปต้องมี `alt` `width` `height` `loading="lazy"` และเครดิตเหมือนรูปในบทความ

| ช่อง | ความหมาย |
|---|---|
| `slug` | ชื่อสั้นภาษาอังกฤษ ไม่ซ้ำกัน ใช้เป็นลิงก์ตรงมาที่การ์ด (`projects.html#<slug>`) |
| `name` | ชื่อโปรเจกต์ |
| `desc_th`, `desc_en` | คำอธิบายไทยและอังกฤษ (ถ้าไม่มี `desc_en` จะใช้ภาษาไทย) |
| `types` | อย่างน้อยหนึ่งใน `website`, `webapp`, `ai` ใส่ได้หลายค่า ใช้กรองและแสดงเป็นป้ายอัตโนมัติ |
| `tags` | ป้ายเพิ่มเติม เช่น `["Python"]` (ไม่ต้องใส่ซ้ำกับ `types`) |
| `url` | ลิงก์เว็บจริงของโปรเจกต์ (แสดงเป็นปุ่มในหน้ารายละเอียด) ถ้าเป็น `""` ปุ่มจะเป็นช่อง `[ลิงก์เว็บจริง]` |
| `github` | ลิงก์ GitHub (แสดงบนการ์ดและในหน้ารายละเอียด) ถ้าเป็น `""` จะไม่แสดง |
| `thumb` | อักษรย่อ 2 ตัวบนการ์ด หรือ path ของภาพ เช่น `assets/img/nexus.png` |

ช่อง `url` และ `github` ที่เป็น `""` คือช่องที่รอข้อมูลจริง (เหมือนข้อความใน `[ ]` ในหน้า HTML)

## ถ้าโหลดข้อมูลไม่ได้

เว็บจะแสดงข้อความแจ้งในหน้าแรกหรือหน้าโปรเจกต์ และช่องค้นหาจะบอกว่าโหลดรายการไม่สำเร็จ (ยังค้นหาหน้าพอร์ตโฟลิโอและเกี่ยวกับฉันได้) สาเหตุที่พบบ่อยคือเปิดผ่าน `file://` หรือ JSON พิมพ์ผิด (ลืมเครื่องหมายจุลภาค) ตรวจ error ได้ที่ Console ของเบราว์เซอร์

## ช่องที่ต้องเติม

ข้อความในวงเล็บ `[ ]` คือที่ว่างรอข้อมูลจริง เช่น รูปโปรไฟล์ ปีที่ได้รางวัล ชื่อรายการแข่งขัน ภาพกิจกรรม เกียรติบัตร และอีเมล ช่องที่เป็นรูปและอีเมลกรอกผ่านชื่อไฟล์หรือ `data/site.json` (ดูหัวข้อ "รูปภาพ" และ "ตั้งค่าเว็บ") ส่วน `[ปี]` กับ `[รายการแข่งขัน]` ในหน้าพอร์ตโฟลิโอแก้ใน HTML ตรงๆ ส่วนลิงก์โปรเจกต์ (`url`) กับ GitHub (`github`) ที่ยังว่างอยู่ใน `data/projects.json` ให้ใส่ที่ไฟล์นั้น และเนื้อหาในหน้ารายละเอียดโปรเจกต์ทุกหน้า (`projects/*.html`) ยังเป็นช่อง `[ ]` ทั้งหมด รอคุณเขียน

## ตั้งค่าเว็บ (data/site.json)

ข้อมูลที่ใช้ซ้ำหลายหน้าอยู่ที่ `data/site.json` ที่เดียว แก้แล้วทุกหน้าเปลี่ยนตาม

| ช่อง | ใช้ที่ไหน |
|---|---|
| `name` | ชื่อในส่วนท้ายทุกหน้า ชื่อผู้เขียนในหน้าแรกและหน้าบทความ หัวข้อหน้าเกี่ยวกับฉันและพอร์ตโฟลิโอ |
| `name_en` | ชื่อภาษาอังกฤษ (ไม่บังคับ ใช้ตอนเลือก EN) ถ้าเป็น `""` ใช้ชื่อไทย |
| `initials` | อักษรย่อในวงกลมข้างชื่อผู้เขียน |
| `initials_en` | อักษรย่อภาษาอังกฤษ (ไม่บังคับ) |
| `email` | อีเมลและปุ่มคัดลอกในหน้าเกี่ยวกับฉัน ถ้าเป็น `""` จะขึ้น `[อีเมล]` และซ่อนปุ่มคัดลอก |
| `github` | ปุ่ม GitHub ในหน้าเกี่ยวกับฉัน ถ้าเป็น `""` จะขึ้น `[ลิงก์ GitHub]` |
| `photo` | ชื่อไฟล์รูปโปรไฟล์ (อยู่ใน `assets/img/profile/`) ใช้ทั้งหน้าเกี่ยวกับฉันและพอร์ตโฟลิโอ |

ข้อยกเว้น: ชื่อใน `<meta name="description">` และ `<title>` ต้องแก้ใน HTML เอง เพราะ crawler ไม่รัน JavaScript

## รูปภาพ

รูปทุกรูปอยู่ใน `assets/img/` แยกตามชนิด: `profile/`, `activities/`, `certificates/`, `projects/`

**ขั้นตอน**
1. วางรูปต้นฉบับ (jpg/png) ใน `img-src/<โฟลเดอร์>/` (โฟลเดอร์เดียวกับชื่อด้านบน ถ้ายังไม่มี สคริปต์จะสร้างให้ตอนรันครั้งแรก โฟลเดอร์ `img-src/` ไม่ถูกอัปโหลดขึ้น GitHub)
2. ติดตั้ง Pillow ครั้งเดียว: `pip install Pillow`
3. รันสคริปต์ย่อรูป

```bash
python scripts/optimize-images.py
```

(บน Windows ถ้า `python` เปิด Microsoft Store แทนที่จะรัน ให้ใช้ `py scripts/optimize-images.py` หรือติดตั้ง Python จาก python.org)

สคริปต์แปลงเป็น `.webp` กว้างไม่เกิน 1600px (รูปที่เล็กกว่าไม่ขยาย) หมุนรูปตามที่ถ่าย และ**ลบข้อมูล EXIF รวมถึงพิกัด GPS ออก** ข้ามรูปที่แปลงไว้แล้ว ไม่แตะไฟล์ต้นฉบับ ตัวเลือก: `--force` (ทำใหม่ทั้งหมด), `--dry-run` (ดูก่อนไม่เขียนไฟล์), `--max-width`, `--quality` ตั้งชื่อไฟล์เป็นอังกฤษ ไม่มีเว้นวรรค (เช่น `cert-math-2568.jpg`)

4. ใส่เฉพาะ "ชื่อไฟล์ .webp" ในช่องที่ต้องการ ไม่ต้องใส่โฟลเดอร์

| รูป | ใส่ที่ไหน |
|---|---|
| โปรไฟล์ | `photo` ใน `data/site.json` เช่น `"me.webp"` |
| ภาพกิจกรรม | `data-file="..."` ของแต่ละช่อง `[ภาพกิจกรรม]` ใน `portfolio.html` |
| เกียรติบัตร | `image` ของแต่ละใบใน `data/certificates.json` (ดูหัวข้อ "เกียรติบัตร") |
| ภาพปกบทความ | `covers[].src` ใน `data/articles.json` (ดูหัวข้อ "ภาพปกแบบสไลด์") |
| ภาพโปรเจกต์ | `thumb` ใน `data/projects.json` เป็น path เต็ม เช่น `"assets/img/projects/nexus.webp"` และภาพหน้าจอในหน้า `projects/<slug>.html` |

ตัวอย่างช่องรูปกิจกรรม: `<div class="ph" data-slot="activities" data-file="lab-1.webp">[ภาพกิจกรรม]</div>` ถ้า `data-file` ว่าง ช่อง `[ ]` ยังอยู่เหมือนเดิม ถ้าชื่อไฟล์ผิดหรือไฟล์ไม่มี ช่อง `[ ]` จะกลับมาแทน (ดูเหตุผลใน Console ของเบราว์เซอร์)

## เกียรติบัตร

เกียรติบัตรในหน้าพอร์ตโฟลิโอสร้างจาก `data/certificates.json` ไม่ต้องแก้ HTML เพิ่มใบใหม่ด้วยการเพิ่มรายการต่อท้าย

```json
{ "title": "ชื่อรายการแข่งขัน", "title_en": "", "year": "2025", "image": "chem-prov-2025.webp" }
```

| ช่อง | ความหมาย |
|---|---|
| `title` | ชื่อรายการ/รางวัล ใช้เป็นคำบรรยายใต้ใบ และเป็น alt ของรูป (ถ้าไม่ใส่ `alt` แยก) |
| `title_en` | ชื่อภาษาอังกฤษ (ไม่บังคับ) ถ้าว่างจะแสดงชื่อไทย |
| `year` | ปี **ค.ศ.** 4 หลัก เว็บแสดงเป็น พ.ศ. ในโหมดไทย (2025 เป็น 2568) และ ค.ศ. ในโหมดอังกฤษ ถ้าไม่ใช่เลข 4 หลักจะแสดงตามที่เขียน |
| `image` | ชื่อไฟล์ใน `assets/img/certificates/` (ย่อด้วย `scripts/optimize-images.py` ก่อน) ว่าง = แสดงช่อง `[เกียรติบัตร n]` ไฟล์ไม่มี = ช่องกลับมาแทนรูปเสีย |
| `alt` | ไม่บังคับ ข้อความแทนรูป |

ช่องว่างใน JSON จะแสดงเป็น `[เกียรติบัตร n]` กับ `[ชื่อรายการ ปี]` จนกว่าจะกรอก ตอนนี้มี 4 ช่องรอข้อมูล

**การแสดงผล**
- **ตั้งแต่ 4 ใบ:** เป็นแถบที่เลื่อนจากขวาไปซ้ายต่อเนื่องที่ **40px ต่อวินาที** ไม่ว่ามีกี่ใบ ขอบซ้ายขวาจางลง ต่อกันไม่สะดุดด้วยการคัดลอกชุดรายการอีกชุด (`aria-hidden` + `inert` ไม่รบกวนโปรแกรมอ่านหน้าจอและ Tab) หยุดเมื่อ hover, เมื่อโฟกัสอยู่ในแถบ, เมื่อแถบพ้นจอ (ไม่มีปุ่มหยุดเลื่อนตามที่ตัดสินใจ)
- **น้อยกว่า 4 ใบ:** แสดงเป็นกริดธรรมดา ไม่มีแถบเลื่อนและไม่มีปุ่ม
- **ตั้งค่าลดการเคลื่อนไหวในระบบ:** ไม่เลื่อนเอง เป็นแถวที่ปัดหรือเลื่อนดูเอง (Tab เข้าไปแล้วใช้ลูกศรเลื่อนได้)
- **กดใบไหนก็ได้:** เปิดดูเต็มจอใน lightbox แล้วเลื่อนดูใบถัดไป/ก่อนหน้าได้ด้วยปุ่มลูกศร ลูกศรซ้าย/ขวาบนคีย์บอร์ด หรือปัดบนมือถือ มีตัวนับ "3 / 6" ปิดด้วย Esc คลิกนอกภาพ หรือปุ่มปิด
- **พิมพ์เป็น PDF:** แถบกลายเป็นกริดที่ตัดบรรทัด ไม่มีใบซ้ำและไม่มีปุ่ม

โค้ดอยู่ที่ `assets/js/certificates.js` กับ `assets/css/certificates.css` (โหลดเฉพาะหน้าพอร์ตโฟลิโอ) ถ้าไม่มีสองไฟล์นี้ เกียรติบัตรยังแสดงเป็นกริดและกดดูเต็มจอได้

## พิมพ์เป็น PDF

หน้าพอร์ตโฟลิโอและเกี่ยวกับฉันมีสไตล์สำหรับพิมพ์ (ซ่อนเมนู ปุ่ม และช่องค้นหา ตัดเป็นหน้าไม่ให้การ์ดขาดกลาง แสดงลิงก์ภายนอกเป็นข้อความ) วิธีทำ: เปิดผ่านเซิร์ฟเวอร์ในเครื่องหรือเว็บจริง → ถ้าต้องการเวอร์ชันใดให้เปิดลิงก์ `#chem` หรือ `#bio` ก่อน (หัวกระดาษจะบอกเวอร์ชัน) → Ctrl+P → ปลายทาง "บันทึกเป็น PDF" ขนาด A4 → ดูตัวอย่างทุกหน้าก่อนบันทึก ช่อง `[ ]` ที่ยังไม่ได้กรอกจะพิมพ์ออกมาด้วย ตรวจให้ไม่เหลือก่อนยื่นจริง

## ขึ้น GitHub Pages

### 1) ตรวจก่อนอัปโหลด

```bash
py scripts/check-site.py
```

ต้องได้ `OK` (ไม่มีลิงก์เสีย รูปไม่มี alt หรือรายการใน `data/*.json` ที่ไม่มีไฟล์จริง) สคริปต์ยังแสดงรายการช่อง `[ ]` ที่เหลือทั้งเว็บ ก่อนยื่นจริงรัน `py scripts/check-site.py --strict` ซึ่งจะไม่ผ่านจนกว่าจะกรอกครบ

### 2) สร้าง repository และอัปโหลด

1. สร้าง repository ใหม่บน GitHub (ต้องเป็น Public ถึงใช้ GitHub Pages ฟรี) อย่าเลือกสร้าง README หรือ .gitignore จากหน้าเว็บ เพราะโฟลเดอร์นี้มีอยู่แล้ว
2. ในโฟลเดอร์นี้ (เป็น git repo อยู่แล้ว) รัน

```bash
git remote add origin https://github.com/<ชื่อผู้ใช้>/<ชื่อ-repo>.git
git branch -M main
git push -u origin main
```

3. ไปที่ **Settings → Pages** เลือก **Source: Deploy from a branch** แล้วเลือก branch `main` โฟลเดอร์ `/ (root)` กด Save
4. รอ 1 ถึง 2 นาที (ดูสถานะที่แท็บ Actions "pages build and deployment") เว็บจะอยู่ที่ `https://<ชื่อผู้ใช้>.github.io/<ชื่อ-repo>/`
5. **ตั้งที่อยู่เว็บจริง** (ต้องทำหลังรู้ที่อยู่ในข้อ 4) แล้วอัปโหลดอีกรอบ

```bash
py scripts/prepare-deploy.py --url https://<ชื่อผู้ใช้>.github.io/<ชื่อ-repo>
git add -A
git commit -m "Set site address"
git push
```

สคริปต์ใส่ที่อยู่ลงใน `[URL เว็บ]` ของ meta แชร์ลิงก์และ hreflang ทุกหน้า สร้าง `sitemap.xml` และ `robots.txt` ใหม่ และเก็บที่อยู่ไว้ที่ `url` ใน `data/site.json` (รันซ้ำได้ทุกครั้งที่เพิ่มบทความ เพื่ออัปเดต sitemap)
6. **ตรวจเว็บจริง:** เปิดหน้าแรก, `/portfolio.html#chem`, ที่อยู่ที่ไม่มีอยู่ (ต้องเห็นหน้า 404 ที่มีสไตล์ครบ), `/robots.txt` และ `/sitemap.xml` แล้วลองกด TH/EN
7. (ไม่บังคับ) ส่ง `sitemap.xml` ที่ Google Search Console ให้ค้นเจอเร็วขึ้น

ข้อควรรู้
- GitHub Pages สร้างเว็บด้วย Jekyll ไฟล์ที่ขึ้นต้นด้วย `_` (เช่น `articles/_template.html`) จึงไม่ถูกเผยแพร่ และ `_config.yml` ซ่อน `README.md`, `CLAUDE.md`, `scripts/` ออกจากเว็บ
- **ชื่อไฟล์แยกตัวพิมพ์ใหญ่เล็ก** บน GitHub Pages (Windows ไม่แยก) ใช้ตัวพิมพ์เล็กทั้งหมดและให้ตรงกับที่อ้างถึงทุกตัวอักษร ไม่เช่นนั้นเปิดในเครื่องได้แต่ขึ้นเว็บแล้ว 404
- เปลี่ยนไฟล์แล้วอาจเห็นของเก่าอยู่ไม่กี่นาที (GitHub Pages แคชไว้ประมาณ 10 นาที) ลองรีเฟรชแรงๆ (Ctrl+Shift+R)

### ถ้าใช้ชื่อ repo อื่น หรือโดเมนอื่น

เว็บใช้ลิงก์แบบสัมพัทธ์ทั้งหมด **เปลี่ยนชื่อ repo ได้โดยไม่ต้องแก้ลิงก์ในหน้าเว็บ** สิ่งที่ผูกกับชื่อมีแค่ตารางนี้

| สิ่งที่ผูกกับที่อยู่ | ต้องทำอะไร |
|---|---|
| `og:url`, `og:image`, `twitter:image`, hreflang, `sitemap.xml`, `robots.txt` | รัน `py scripts/prepare-deploy.py --url <ที่อยู่ใหม่>` สคริปต์จะแทนที่อยู่เก่า (จาก `data/site.json`) ด้วยที่อยู่ใหม่ทุกหน้า แล้ว commit และ push |
| `404.html` (หา `<base>` เอง) | `SITE_BASE` เป็น `null` = เดาชื่อ repo จากที่อยู่ ใช้ได้กับ project site (`user.github.io/<ชื่อ-repo>/`) และโดเมนของตัวเอง ถ้า repo ชื่อ `<ชื่อผู้ใช้>.github.io` (user site ที่ไม่มีชื่อ repo ต่อท้าย) ให้แก้บรรทัด `var SITE_BASE = null` ใน `404.html` เป็น `'/'` |
| รูปแชร์ลิงก์ของแต่ละบทความ | path ของรูป (`[path รูปปก]`) ไม่ขึ้นกับชื่อ repo ต้องกรอกเองครั้งเดียวต่อบทความ |
| โดเมนของตัวเอง (custom domain) | ตั้งที่ Settings → Pages → Custom domain (GitHub สร้างไฟล์ `CNAME` ให้) แล้วรัน `prepare-deploy.py --url https://<โดเมน>` |

ไฟล์ favicon: `favicon.svg` คือต้นฉบับ (สี่เหลี่ยมสี `--accent` เหมือนโลโก้) ส่วน `favicon-32.png`, `favicon.ico`, `apple-touch-icon.png` สร้างจากสีเดียวกัน ถ้าเปลี่ยนสี accent ต้องทำไฟล์เหล่านี้ใหม่
